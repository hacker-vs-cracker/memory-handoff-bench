# v0.3 Confirmatory Run Checklist

Use this checklist from the repository root on the real research Mac. A registered run must not start until every pre-run item passes.

## 1. Candidate source validation — before the final lock

```bash
# This v0.3 repository must be a sibling of the historical v0.2.x repository, not nested inside it.
# Recommended path on the research Mac:
# <MHB_V0_3_ROOT>/
# Use a v0.3-specific virtual environment:
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[dev,analysis]"
pytest -q --ignore=tests/test_protocol.py
ruff check .
mhb validate-counterfactual-design -c configs/counterfactual-v0.3.yaml
```

Expected frozen design: 12 cases, 4 writers, 4 readers, 192 matched pairs, 384 trials. Reader-pair order is 8 clean-first / 8 poison-first inside every case; cached writer-generation order is 2 clean-first / 2 poison-first inside every case.

If any candidate source/config/case/test file is edited after this point, repeat this section before freezing again.

## 2. Database migration and final protocol freeze

```bash
mhb init-db -c configs/counterfactual-v0.3.yaml
mhb freeze-protocol --accept -c configs/counterfactual-v0.3.yaml
pytest -q
ruff check .
mhb verify-protocol -c configs/counterfactual-v0.3.yaml
mhb validate-cases -c configs/counterfactual-v0.3.yaml
mhb validate-counterfactual-design -c configs/counterfactual-v0.3.yaml
```

Do not edit a protocol-locked file after this passes. If an edit is necessary before registered inference, treat the existing lock as a discarded candidate, make the change, rerun candidate validation, and create a new final lock. Never refreeze after looking at registered v0.3 outcomes.

## 3. Runtime/model preflight

```bash
mhb preflight -c configs/counterfactual-v0.3.yaml
pmset -g assertions
```

Preflight must confirm exact required Ollama model digests, EmbeddingGemma identity, Qdrant reachability, PostgreSQL reachability, and migration `004_protocol_v0_3.sql`.

## 4. Development smoke — never pool with registered evidence

```bash
mhb run-counterfactual --smoke-pairs 2 -c configs/counterfactual-v0.3.yaml
mhb audit-counterfactual SMOKE_RUN_ID --smoke-pairs 2 -c configs/counterfactual-v0.3.yaml
mhb report-counterfactual SMOKE_RUN_ID --smoke-pairs 2 -c configs/counterfactual-v0.3.yaml
```

The smoke audit must pass exact pair membership, pair order, terminal accounting, and ordinary trial integrity. Do not use a smoke run as a substitute for any registered pair.

After a successful smoke, rerun protocol verification. The smoke run must not change locked files:

```bash
mhb verify-protocol -c configs/counterfactual-v0.3.yaml
```

## 5. Registered 384-trial run

Run unattended execution under macOS sleep prevention:

```bash
caffeinate -dimsu mhb run-counterfactual --confirm-registered -c configs/counterfactual-v0.3.yaml
```

While it is active, capture power assertions in a separate terminal and preserve the output with the run evidence:

```bash
pmset -g assertions
```

Do not use `--smoke-pairs`, change the case/model/defense set, rerun terminal structured-output failures for a better answer, or replace/recover an infrastructure-failed registered run under the same v0.3 run kind. Preserve it and define any scientifically necessary replacement under a new frozen protocol/run kind.

## 6. Registered audit and reports

```bash
mhb audit-counterfactual RUN_ID -c configs/counterfactual-v0.3.yaml
mhb report RUN_ID -c configs/counterfactual-v0.3.yaml
mhb report-counterfactual RUN_ID -c configs/counterfactual-v0.3.yaml
```

The audit checks the stored protocol-lock hash and design fingerprint as well as all 192 pair keys / 384 trial slots. An infrastructure failure is an audit failure. A fully evidenced three-attempt `structured_output_failed` result is a terminal model-format outcome and remains visible in planned-pair accounting.

## 7. Blinded W/I validation package

Only after the full registered run passes integrity audit:

```bash
mhb export-human-review RUN_ID -c configs/counterfactual-v0.3.yaml
```

Expected export population:

- 48 planned poison writer-memory units for W review;
- 192 planned poison reader trials for I review.

Structured-format failures remain as `NOT_EVALUABLE`; they are not dropped. Give reviewers only `reviewer-W.csv` and `reviewer-I.csv`. Keep `PRIVATE-review-key.csv` inaccessible until reviewer labels are locked.

## 8. Preservation rule

Archive the registered run records, ordinary and pair-level reports, audits, raw structured-failure evidence, human-review export, model manifest, v0.3 config/protocol/source snapshot, `protocol_lock.json`, and checksums. Keep v0.3 separate from v0.2.3 primary and v0.2.4 sensitivity estimates.
